Verified exact input: `C:\Users\Administrator\Desktop\lapis-device-tree-bootstrap\lapis_global_images_OS3.0.309.0.WPPMIXM_16.0\images\super.img`; length 8,747,112,524 bytes; SHA-256 `03211CF8BF8A44DDB26D64BB46E5798BE675036C139D60F27A94ABDFA05124E6`.

The first 4 bytes are `3A FF 26 ED`, matching Android sparse image magic `0xed26ff3a` in little-endian form. The sparse header fields report block size 4096 and total blocks `0x002c0000`, corresponding to an expanded size of 11,811,160,064 bytes (~11.0 GiB). AOSP's current `lpdump`/`lpunpack` source explicitly rejects Android sparse input, so first convert a copy into a separate scratch location with AOSP `simg2img`; then use `lpdump` for metadata only. AOSP source references: [libsparse/simg2img build definition](https://android.googlesource.com/platform/system/core/+/HEAD/libsparse/Android.bp), [dynamic partition tools and lpdump usage](https://android.googlesource.com/platform/system/extras/+/refs/heads/main/partition_tools/README.md), [lpunpack sparse-input check](https://android.googlesource.com/platform/system/extras/+/refs/heads/main/partition_tools/lpunpack.cc). ### Commands prepared, not executed

Build or obtain compatible tools from the official AOSP source repositories above in an isolated WSL/Linux environment; do not download standalone binaries from third-party mirrors. Example assumes the tools are already built and available at `/usr/local/aosp-tools/bin`. Set scratch on WSL's Linux filesystem (not the ROM folder):

```bash
INPUT='/mnt/c/Users/Administrator/Desktop/lapis-device-tree-bootstrap/lapis_global_images_OS3.0.309.0.WPPMIXM_16.0/images/super.img'
SCRATCH="$HOME/lapis-super-inspect"
TOOLS='/usr/local/aosp-tools/bin'
mkdir -p "$SCRATCH"
sha256sum "$INPUT"
"$TOOLS/simg2img" "$INPUT" "$SCRATCH/super.raw"
"$TOOLS/lpdump" --slot=0 "$SCRATCH/super.raw"
"$TOOLS/lpdump" --slot=1 "$SCRATCH/super.raw"
```

`lpdump` reports logical partition names, group membership, attributes, extents, and partition sizes without extracting partition filesystem contents. It is the correct first inspection step. Verify slots supported from the output; if slot 1 is absent, its query may report an error and should not be treated as evidence of corruption.

Later, only after approval and after reviewing `lpdump`, extract selected partitions using their exact reported names into a different subdirectory, for example:

```bash
mkdir -p "$SCRATCH/selected"
"$TOOLS/lpunpack" -p '<exact_partition_name_from_lpdump>' "$SCRATCH/super.raw" "$SCRATCH/selected"
```

Do not substitute a guessed partition name or run `lpunpack` without `-p` for this limited workflow. Read-only inspection of source is intended; write access is confined to `$SCRATCH`.

AOSP host tools must match the image's metadata format and host architecture. WSL conversion reads the original from `/mnt/c` but can be slow; raw scratch should remain in WSL's native filesystem and must not overwrite the input. `lpdump` metadata does not establish Android release or vendor API; that requires later property inspection from selected logical partitions.
